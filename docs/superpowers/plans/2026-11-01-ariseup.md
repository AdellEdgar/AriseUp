# AriseUp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App Android que simula el Sistema de Solo Leveling para ejercicio y dieta: misiones, XP, niveles, rangos, stats, Zona de Penalización, registro de comidas estilo MyFitnessPal y una silueta que refleja el cuerpo del usuario.

**Architecture:** Dos módulos Gradle. `:domain` (Kotlin/JVM puro) contiene todas las reglas del juego como funciones puras y se prueba sin Android. `:app` (Compose + Room + WorkManager) persiste el estado, orquesta el cierre de día, integra Open Food Facts, ML Kit y Health Connect, y dibuja la interfaz del Sistema.

**Tech Stack:** Kotlin, Jetpack Compose + Material 3, Navigation Compose, Room (KSP), DataStore, WorkManager, Ktor client + kotlinx.serialization, CameraX + ML Kit Barcode (bundled), Health Connect client, Vico (gráficas), JUnit 5 + Kotest property, Robolectric, Python 3 para el script de la tabla genérica.

**Spec:** `docs/superpowers/specs/2026-11-01-ariseup-design.md`

## Review Focus

1. **App sin abrir varios días / móvil apagado:** al volver, se cierran en orden todos los días pendientes y la degradación (incluida la bajada de nivel desde el 3er cierre) se aplica exactamente una vez por día. → test en Tarea 8 (`DayCloser`) y Tarea 11 (`DayCloseCoordinator`).
2. **Hora de reinicio distinta de medianoche y cambio de hora (DST):** el "día de juego" de un instante es correcto a ambos lados del cambio, y un retroceso de fecha no reabre días. → test en Tarea 2 (`GameDay`) y Tarea 11.
3. **Doble toque / registro repetido al completar una misión:** la recompensa se concede una sola vez. → test en Tarea 10 (`MissionRepository.complete`).
4. **Producto de Open Food Facts incompleto o solo en kJ / solo por ración:** se guarda, kJ→kcal (÷4,184), campos ausentes = 0 y marcado `incomplete = true`. → test en Tarea 17.
5. **Importar una copia corrupta o de un esquema futuro:** se rechaza sin tocar los datos actuales. → test en Tarea 19.
